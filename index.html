✨ What It Does

Built around the four objectives in the project brief: layout-aware parsing, granular extraction, semantic ranking and explainability.

🧾

Layout-aware parsing

Finds the column gutter on each PDF page and reads columns separately, so a skills sidebar never bleeds into job history.

🧩

Structured extraction

Jobs with title, company and duration, education, contact details and quantified achievements, serialised to JSON.

🕸️

Skill ontology

70+ canonical skills with aliases (K8s → Kubernetes, GCP → Google Cloud), implied skills and adjacency scores.

🎯

Two-stage ranking

Fast retrieval over the whole pool, then a passage-level rerank that compares the JD with each job separately.

💬

Explainable scores

Three bullets per candidate: what matches, the strongest evidence, and the honest caveat.

🙈

Blind mode

Redacts names, contacts, graduation years, personal-details blocks and identity-linked groups before scoring.

👯

Look-alike search

Pick a strong candidate and find the nearest neighbours in the pool, no Boolean query needed.

✉️

Outreach drafts

Personalised first email that quotes a real achievement from the resume and ties it to the role.

🧭 How It Works

From a folder of resumes to a ranked, explained shortlist.

Extract

pdf.js gives text with x/y positions; DOCX is unzipped and read paragraph by paragraph. Tiny hidden text is dropped.

Structure

Sections, date ranges, overlapping jobs, internships (counted at half weight), degrees and metrics.

Normalise

Skills mapped to canonical ontology nodes, implied skills added, per-skill tenure computed.

Blind

PII and identity signals are masked. Only the redacted text is used for semantic scoring.

Rank & explain

Retrieval → rerank → fit score, then explanations, flags and recruiter feedback.

📐 Fit Score Algorithm

Deep similarity is combined with hard business rules, the same 50 / 30 / 20 split as the brief's heuristic multiplier matrix. Recruiters can change the weights live.

50%

Semantic Match

TF-IDF cosine with canonical skill tokens (stage 1), blended with the best and average job-level passage similarity (stage 2), recent roles weighted higher.

30%

Experience

Full credit at or above the JD's requirement; below it the score decays exponentially with the relative shortfall. Overlapping jobs count once.

20%

Skill Overlap

JD-anchored soft overlap: exact = 1, inferred = 0.85, listed-only = 0.75, adjacent skill = 0.25–0.75 (e.g. Azure for AWS = 0.7). Plain Jaccard is reported too.

fit = 100 × ( 0.5 · semantic + 0.3 · experience + 0.2 · skills )
experience = 1 if years ≥ required, else e−2 · (required − years) / required
semantic = s / (s + 0.18), s = 0.5 · retrieval + 0.3 · best_passage + 0.2 · avg_passage

🛡️ Ethical AI & Bias Mitigation

Scoring only sees what is relevant to the job.

What gets redacted

Names, email, phone, address lines, profile links, graduation years, DOB / gender / religion / marital-status lines, gendered pronouns, and identity-linked group names ("… Women's Association" → "University Association").

Keeping the score honest

Skills that only appear in a long skills list get reduced credit and a keyword-stuffing flag. 1–3pt hidden text in PDFs is discarded. Every score comes with its reasons, so a recruiter can disagree with it.
